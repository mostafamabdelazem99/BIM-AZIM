Architecture

How it works

A three-layer design connecting AI to three different BIM APIs — each wired the way its own API actually works.

AI Client Layer Claude Desktop · Claude Code · ChatGPT · Cursor · VS Code · any MCP client
↓ MCP protocol (stdio / JSON-RPC)
BIM-AZIM MCP Server Node.js + TypeScript · tool registry · routes to the right engine bridge
↓ HTTP/JSON, one port per engine
Revit Add-in In-process · :8080
Navisworks Add-in In-process · :8091
Tekla Bridge Service Out-of-process · :8092
Built honestly: the Tekla bridge code was written against my knowledge of the Tekla Open API, but wasn't compiled or run against a live Tekla Structures install in this environment. Every spot worth double-checking is flagged // VERIFY: in the source, with the full checklist in docs/TEKLA_INTEGRATION.md.
New Integration

Why Tekla Structures connects differently

Revit and Navisworks only expose their APIs to code running inside their own process. Tekla's Open API is built to be called from the outside.

① No in-process add-in required

new Tekla.Structures.Model.Model() from any external .NET process connects straight to the running Tekla Structures session over Tekla's own remoting layer.

② Runs as its own service

The bridge can be started, stopped, and updated independently of Tekla itself — no reloading an add-in, no restarting Tekla to pick up a fix.

③ Same contract as the others

GET /health and POST /tools/:name — identical shape to the Revit and Navisworks bridges, so the MCP server treats all three uniformly.

Manual setup

Prefer to build it yourself?

# 1. Build the MCP server cd server npm install npm run build # 2. Build the Tekla bridge (after setting TeklaStructuresBin — see plugins/Tekla/README.md) cd ../plugins/Tekla/BimAzim.TeklaBridge dotnet build # 3. Point your AI client at the server (see server/README.md for the full JSON)
1

Build the server

TypeScript MCP server in server/ — registers all Revit/Navisworks/Tekla tools.

2

Build the Tekla bridge

Point TeklaStructuresBin at your install, verify the flagged API calls, then build.

3

Point your AI client at it

Add the server to Claude Desktop / Claude Code / Cursor's MCP config.

4

Check engine status

Ask your AI client to call bimazim_engine_status before anything else.
